# Migrations

Drizzle migrations for IW-Generator.

## Deployment strategy

The first migration (`0000_phase_1_foundations.sql`) is a **full schema baseline**. It generates CREATE TABLE for every table in `shared/schema.ts`, including tables that may already exist on a production database (`users`, `wills`, `scheduled_jobs`, `assistance_requests`).

**For fresh environments (dev / staging):** apply the migration directly.

```bash
DATABASE_URL=postgresql://... npx drizzle-kit migrate
```

**For the existing production DB** (which already has `users`, `wills`, etc. from Riaz's original VIAR-Devs deployment): use `drizzle-kit push` — it diffs against the live schema and applies only the delta (the five new Phase 1 tables + new columns on `users`). Do NOT run `drizzle-kit migrate` against a populated DB — the migration will fail because it tries to re-create existing tables.

```bash
DATABASE_URL=postgresql://... npx drizzle-kit push
```

After the first production push, future migrations generated by `drizzle-kit generate` will be proper deltas.

## Spec

See `00_foundation/specs/iw-generator-conversational-spec-v1.md` (Context OS) for the architecture these tables support. Summary of Phase 1 additions:

| Table | Purpose |
|---|---|
| `consents` | Three-way consent model: service_delivery / ecosystem_matching / marketing |
| `user_context` | Ecosystem routing signal (estate size band, migration intent, giving intent, preferred causes, etc.) |
| `email_events` | Time-series log from Resend webhook (sent / delivered / opened / clicked / bounced / complained / unsubscribed) |
| `conversation_sessions` | One row per conversational session — full transcript + beat state for resume |
| `gaps_analysis` | One row per will issuance — personalised gap list + CTA click telemetry |

Plus engagement columns added to `users`: `last_opened_at`, `last_clicked_at`, `open_count`, `click_count`, `bounce_status`, `unsubscribed_at`.
